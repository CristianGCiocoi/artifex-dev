# ARTIFEX Architecture

1. Read accepted requirements, constraints, assumptions, interfaces, invariants, and relevant research only.
2. Separate observed facts, accepted authority, assumptions, and proposals.
3. Compare viable alternatives against explicit decision drivers, risks, operational cost, and reversibility.
4. Specify component ownership, stable contracts, failure behavior, security boundaries, migration, rollback, and validation impact.
5. Produce an ADR or architecture candidate with traceability and revisit triggers.
6. Stop at the Architect/Human gate for major architecture changes. A candidate or test result is not authorization.

Preserve agent neutrality, Git/filesystem truth, graceful degradation, privilege non-escalation, and research authority separation.
