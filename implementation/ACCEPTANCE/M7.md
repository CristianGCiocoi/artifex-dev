# M7 — Active Implementation Record

M7 began from canonical `main` at
`14da51f530bd859afebf1ce2d9ed0348a8832f33`, after M6A acceptance and the
fail-closed M8B/M8C integration were published.

The platform-neutral managed-service, installation, bootstrap, doctor, manual
fallback and qualification-harness foundation is implemented and black-box
verified from a clean installed wheel.

The Product Owner resolved the qualification matrix on 2026-08-28. Core GA is
qualified on three independent Windows 11 24H2 or 25H2 x64 clean-VM cells: Codex-only
for J01 and J16, Claude-only for J02 and J16, and no-provider for J10. Provider
coexistence is not required by M7 and no result may be inferred across cells.
The Product Owner explicitly added 25H2 eligibility on 2026-08-28 and then
designated it the preferred newer baseline; the active qualification environment
therefore uses 25H2.

M7 is now `ACTIVE`, not `ACCEPTED`. The Windows 11 per-user Task Scheduler
adapter and public distribution lifecycle are implemented and source-qualified,
but they are not yet qualified from the single provenance-bound shipping
candidate on the three clean-VM cells. The approved per-user service model uses
`InteractiveToken`; each cell therefore records an interactive user logon before
service activation and makes no pre-logon headless-start claim. Developer-machine,
combined-provider and source-tree evidence remain ineligible.

The VM104 qualification base was generalized and independently first-booted on
2026-08-29. The pre-generalization snapshot is explicitly invalid for M7 evidence
because it duplicated the qualification client's Machine SID. The current reset
source for cell execution is `m7-qualified-25h2-x64-cell-base-v3`, derived through
`m7-generalized-25h2-x64-base` and the retained v1/v2 predecessor resets, on
Windows 11 Pro 25H2 build `26200.9168`. V3 contains the repaired, release-finalized
native candidate built from `bf9d4a3a4c0e8c994761c9f2dfefb2f1821f7d6b`;
the earlier reset candidates cannot supply current cell evidence. The
post-generalization SID is distinct, RDP reached the final desktop,
Codex/Claude/Node remain absent,
and transient AutoLogon, unattend, RDP credentials and update payloads were
removed. This establishes the clean reset foundation only; J01, J02, J10 and
both J16 provider cells remain unclaimed until their live outcomes pass.
